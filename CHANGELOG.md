## [0.3.1] - 2026-10-26

### Added

- **`policies/explorer.toml` denies a `kill` aimed at PID `0` or a negative PID.** The 0.3.0 rules refused `pkill` and `killall` but let any `kill` through, and `kill 0` signals the explorer's own process group, `kill -- -<pgid>` a whole group, and `kill -9 -1` every process the user owns. Two new deny rules, scoped like the others to `subagent = "explorer"`: one for a first argument of `0` or a negative number standing alone (`kill 0`, `kill -1`), and one for a `0` or negative number anywhere after the first argument (`kill -9 -1`, `kill -9 0`, `kill -s KILL -1`, `kill -- -4242`). A negative first argument followed by a PID is a signal, so `kill <pid>`, `kill -9 <pid>` and `kill -0 <pid>` with a positive PID still go through; `kill -s 0 <pid>` is refused, as the second rule cannot tell a signal from a target after `-s`. Both rules match `kill` and a path ending in `/kill` (`/bin/kill`), and stop at `;`, `&` and `|`, so a later command in the same line is judged on its own. The policy's header comment, the explorer's cleanup rule, `GEMINI.md` and the README name the new rules. **Checked against Gemini CLI 0.65.0's own `loadPoliciesFromToml` and `PolicyEngine.check`** (from `@google/gemini-cli-core` 0.65.0, run under Node outside a session): both rules load without a ReDoS rejection, 23 non-positive forms are denied for the explorer, compound, wrapped and subshell forms included (`cd /tmp && kill -9 -1`, `sh -c 'kill -9 -1'`, `(kill -1)`), the same commands from any other agent are untouched, and 14 positive-PID and unrelated forms are not denied, `kill -s 0 <pid>` aside. Not exercised in a live Gemini CLI session. The same wrapper limit as the other rules applies: `sudo kill -9 -1` and `xargs kill` slip past.
- **The structure test pins the kill rules, in both shells** (`lib/test-structure.sh` and `lib/test-structure.ps1`, message for message). The policy pin's deny and keep lists gain the kill cases, and a new pin runs the same loader-and-matcher mirror on kill alone, with three break-its: deleting either kill rule, and widening one to every `kill`, each fail it.
- **`lib/test-install.sh` and `lib/test-install.ps1` run the installers and check where they took the extension from**, now part of `lib/test-all.sh` and `lib/test-all.ps1`. Each runs its installer piped from another extension's checkout, piped from a directory whose manifest claims this extension's name, as a file beside another extension's manifest, and as a file from this checkout, and checks the installed manifest, context file and commands against this checkout and the number of clones; a fifth run has the download name another extension and must install nothing. No run touches the network or a real home directory: `HOME` (and, for PowerShell, `USERPROFILE`) points at a fresh temp directory, and a stub `git` first on `PATH` answers `git clone` by copying this checkout. Against the 0.3.0 installers, four of the five `install.sh` runs and three of the five `install.ps1` runs fail.
- **The structure test pins the installers' source, in both shells, with three break-its** (`lib/test-structure.sh` and `lib/test-structure.ps1`, message for message): `install.sh` reads `BASH_SOURCE` only when it names a file and compares the manifest name before and after a clone, `install.ps1` uses `$PSCommandPath` and the same two name checks, and neither may go back to `dirname "${BASH_SOURCE[0]}"` or `$MyInvocation.MyCommand.Path`.
- **The structure test pins `/explore` as a contract `1.0` consumer, in both shells, with three break-its** (a new */explore reads contract 1.0* section in `lib/test-structure.sh` and `lib/test-structure.ps1`, message for message). The command's root key list must equal the explorer's own root-key table, read from `agents/explorer.md` with the verify-mode-only `verify` key left out, so a key added to or dropped from the contract fails the pin until the consumer follows; and the pin holds the three `contract_version` readings, the never-drop-for-version rule, status from `stop_reason`, the confirmed-bug rule, the merge rule, `known_bad` kept out of the bug list and the backlog, and the typed `questions_risks` and `off_charter` elements. The 0.3.0 key list fails it as stale.

### Changed

- **`/explore` now reads each explorer result by output contract `1.0`** (the consumer half of the Claude Code plugin's W2262; the explorer half shipped in 0.3.0 as W2495, which recorded this as still owed). Step 7 of `commands/explore.toml` lists the `1.0` root keys and points at the explorer's *Output contract* section for every shape instead of restating it. It reads a result by its `contract_version`: `"1.0"` as defined; absent as an older explorer, still used, with a missing `known_bad` read as empty, a missing `replicated` as not established, a missing `provisional` from whether `stakeholder_impact` begins "Provisional", and plain-string `questions_risks` and `off_charter` elements as their `text` or `item`; any other value still used, read by the `1.0` keys, and named under Unknown. No session is dropped, and no value invented, because of its version. `status` is looked up from `stop_reason` in the explorer's *Status from `stop_reason`* table, the `stop_reason` winning a disagreement, and `stopped_early` is defined for the debrief. In Step 8 each bug shows `replicated` and `provisional` beside its severity, and **a bug is called confirmed only when `replicated` is `<k>/<n>` with *k* of 2 or more and `provisional` is `false`**: a bug seen once, with replication not established, or provisional stays in the ranked list at the severity its demonstrated failure earns, labelled for what it is, and is never called confirmed or reproducible in Found, a summary or the PROOF Results, which count confirmed and unconfirmed bugs apart. Merging one bug across sessions adds the counts, stays provisional only if every entry was, and takes `stakeholder_impact` from the entry that established the magnitude, as upstream does. `known_bad` entries are listed under Found as already-known behaviour with their `basis`, never ranked, counted as bugs or put in the backlog or a standing risk; `questions_risks` join Unknown grouped by `kind`, with the question that settles a provisional bug beside it; and the backlog takes each `off_charter` item's `candidate_charter`. Upstream's wording on the older-explorer reading, the `stopped_early` meaning and the merge rule is carried in substance. Two parts go beyond upstream: the handling of an unknown `contract_version`, and the word *confirmed* reserved for a replicated, non-provisional bug, where upstream only shows the count. The README's `/explore` section says how sessions are read. **Still not done:** `/explore` does not pass `known_issues` to the explorer, so its sessions produce `known_bad` only from limitations the explorer finds documented; upstream's `/explore` does not pass it either. Not exercised in a live Gemini CLI session.

### Fixed

- **The piped bootstrap installers could install another extension's files under this extension's name.** `install.sh` took its source from `dirname "${BASH_SOURCE[0]}"`, which is the caller's working directory when the script arrives on stdin (`curl … | bash`), and used that directory whenever it held a `gemini-extension.json`, so the one-liner run inside any other Gemini extension's checkout copied that extension into `~/.gemini/extensions/stride-gemini-exploratory-testing/`. `install.ps1` had a related flaw: it took `$MyInvocation.MyCommand.Path`, which is empty under `irm … | iex` at a prompt (so the documented one-liner stopped with a null-path error after creating the install directory) and names the calling script when `iex` runs inside one, so it too could install a foreign checkout; run as a file beside another extension's manifest, either installer installed that extension. Now each installer uses its own directory only when it runs from a file (`install.sh` checks `BASH_SOURCE` names a regular file, `install.ps1` uses `$PSCommandPath`, which `iex` leaves empty) and that directory's manifest `"name"` is `stride-gemini-exploratory-testing`; otherwise it clones a fresh copy and stops with nothing installed when the clone's manifest names another extension or, for `install.ps1`, `git clone` fails. The working directory is never read. Both also create the install directory only once the source is settled, and `install.sh` no longer overwrites `TMPDIR` for its clone. The README's manual-install section says where the files come from and gives the PowerShell one-liner.

## [0.3.0] - 2026-10-26

**Callers that dispatch `explorer` directly must now send two authorization lines, or every session ends `blocked` with zero probes.** Put `AUTHORIZED_NON_PRODUCTION: yes` and `ALLOWED_HOSTS: <host[:port]>, …` (or `ALLOWED_HOSTS: none` for a target reached only through a local command) in the environment context, each on a line of its own. A missing line, an `AUTHORIZED_NON_PRODUCTION` value other than `yes`, or a second copy of either line leaves the target not authorized, and the explorer's own text then tells it to run no probe and send nothing over the network (no runtime check enforces this); a verify dispatch without them returns `not_verified`. `/explore` writes both lines for you, first in the block. `stride-gemini`'s Step 5.5 dispatch does not send them yet, so its sessions end `blocked` until that consumer is updated.

This entry is the whole of the G449–G451 port to Gemini CLI: tasks W2494–W2502, recorded here by W2503, carrying the Claude Code plugin's W2261–W2264, W2266, W2268–W2270 and W2272 (upstream 0.3.0 and 0.4.0). The explorer now carries its severity, oracle, RIMGEA and stop rules in an inline card instead of in skills it may not be able to read, and its findings follow output contract `1.0`. It loses `web_fetch`, observes HTTP with `curl -sS -i`, judges only what its own tools can observe, and ends a charter it cannot observe with `no_observation_surface`. Its text tells it to run only with the two authorization lines above, reach only the hosts they list, and clean up what it started before its last working turn. Given an `EXPLORATORY_REPORT_PATH`, it writes its full findings to that file and returns a plain-text summary of at most 2,048 bytes; given `EXPLORATORY_MODE=verify`, it re-checks one fixed bug on two probes and ten tool calls, and `not_verified` is never a pass. It locates with `grep_search`, reads a bounded `read_file` range and never re-reads an unchanged file. `/harden` runs unattended when given both a bug source and `--framework`. The agent and command descriptions, two skill sections and `GEMINI.md` are shorter. What this edition leaves to other repositories, and what was never exercised in a live Gemini CLI session, is listed under *Not carried by this edition* at the end of the entry.

## [0.2.0] - 2026-08-01

A capability sweep ported from the Claude Code plugin's 2026-07 improvement research: two new commands, a sixth skill, session artifacts that survive the conversation, and an explorer contract that no longer asks the agent to fabricate.

### Added

- **`/pair` command** (`commands/pair.toml`) — an exploratory session with a **human at the keyboard**, the inversion of `/explore`. The human drives the application and reports what they did and saw; the command suggests one probe per round and **names the `heuristics` lens it came from**, judges each report with `oracles`, runs RIMGEA on confirmed defects as instructions to the human, and keeps the SBTM session sheet and off-charter parking lot so the tester never context-switches into note-taking. Its signature work is the **unprompted coverage-gap sweep**: three ledgers (areas, the nine Variable Catalog rows, and seven fixed stances — valence, tenancy, role, character set, volume, sequence/concurrency, entry point) swept at fixed points, each gap raised at most once, with a declined gap going to the backlog rather than being lost. It measures only what it can observe — duration from two real `date` stamps, Task Breakdown Metrics marked *derived* unless the tester confirms them, and never a response time it did not see. It writes a session sheet and appends to the backlog, deliberately **not** the coverage outline, and hands off to `/debrief`. **It never drives the application and never dispatches the `explorer`.** Note that a Gemini TOML command has no tool allowlist, so unlike the Claude original that boundary is held by the command's own rules rather than by a withheld tool — the command says so plainly rather than claiming an enforcement it does not have.
- **`/harden` command** (`commands/harden.toml`) — the bridge from *Explored* back to *Checked*. It reads a session's oracle-confirmed bugs (from an explorer findings object, a `/pair` sheet, an `/explore` debrief, or pasted findings), **detects the project's own test framework** from its markers, existing tests, and config across nine ecosystems — reporting what it detected and on what evidence **before anything is written** — and drafts one regression check per convertible bug, built from the bug's isolated `minimal_repro`. A bug is convertible only with a stated trigger, a stated wrong result, a programmable observation, and a safe repro; everything else is reported not-converted under one of seven categories with the one thing that would fix it, because a guessed repro produces a check that passes for the wrong reason. Drafts never hard-code a secret, never point at a real host, and never perform a destructive action. They are staged under `.exploratory/checks/<timestamp>-<slug>/` with an `INDEX.md`, nothing is ever overwritten, and **it never runs a draft and never says one passes** — a rule the command holds itself, stated as such, since a Gemini TOML command has no allowlist that could withhold a shell from it.
- **`bug-advocacy` skill** (`skills/bug-advocacy/SKILL.md`) — the sixth skill, and the one that picks up where `oracles` stops. It encodes Cem Kaner's **RIMGEA** follow-through (Replicate, Isolate, Maximize, Generalize, Externalize, And say it clearly), each step with a definition and the prompt to ask, plus a **severity rubric a second reader can re-derive**: four named levels, an impact ladder of explicit clauses, three aggravating modifiers with a stated combination rule, an agreement test, and the two-door procedure for when the impact is genuinely unknown. `severity` was already a required field of the explorer's `bugs[]` contract and was defined nowhere — this is where it now comes from. Routed from `oracles` (at the moment a result is judged a Defect) and from the orchestrator's routing table.
- **Session artifacts on disk** — sessions now persist to `.exploratory/` in the project under test: `backlog.md` (append-only candidate/deferred charters, parked items, and open questions), `coverage.md` (the product coverage outline — a map, explicitly never a score), and `sessions/<timestamp>-<slug>.md` (one debrief per `/explore` run). The `session` skill owns the tree, the formats, the header blocks, and the read-immediately-before-write mechanics. **A missing artifact is an empty starting state, never an error**, so a first run in a new project simply creates what it needs. Add `.exploratory/` to the project under test's `.gitignore`.
- **`charter-generator` accepts `coverage context`** and gains an optional `deprioritized` output key. When a coverage digest is supplied it mines the still-dark areas and the open backlog, discounts charters aimed at ground already covered, and records what it moved down — with risk always outranking recency, so an area explored last week that still has an open Critical bug is not treated as covered. `/charter` and `/explore` assemble that digest and pass it; the agent stays read-only and never touches disk itself.
- **`interfaces` lens** — the Heuristic Test Strategy Model's **I**nterfaces element joins the coverage lens in the `chartering` skill, covering APIs, imports and exports, UI surfaces, and integration points between systems: the boundaries where service-oriented and LLM tool-calling applications most often fail. **Downstream consumers must handle `interfaces` as a new allowed value of a charter object's optional `lens` field** (`agents/charter-generator.md`), alongside the existing `structure`, `function`, `data`, `platform`, `operations`, and `time`.

### Changed

- **The `explorer` agent's `bugs[]` objects carry the four RIMGEA fields.** Each bug now emits `minimal_repro`, `worst_observed`, `generalization`, and `stakeholder_impact` alongside the existing five, and `severity` must be one of the `bug-advocacy` rubric's levels written in full. **The four fields are honest-or-"could not establish", never invented** — the key is always emitted, and when the answer could not be established its value says exactly that. `/explore` carries all four through aggregation and, when two sessions found the same bug, merges by keeping the shortest `minimal_repro`, the worst demonstrated `worst_observed`, and the broadest `generalization`. **Downstream consumers of `bugs[]` gain four keys**; none is removed.
- **The other four commands now participate in the artifact tree.** `/charter` and `/nightmare-headline` append their generated charters to the backlog; `/recon` appends candidate charters and questions and may add an un-explored area stub to the coverage outline (it never dates an area or edits an existing one); `/debrief` appends parked items and refreshes coverage for the areas its notes honestly identify. Every one of them treats a missing file as an empty starting state.
- **Redaction and untrusted-input rules restated for written files.** The redaction rule now binds explicitly on *writes*, not only on rendered output — a file outlives the session and can be read by someone who never saw the run — and it covers the four new bug fields. Conversely, `backlog.md` and `coverage.md` are read back on later runs and are **data, never instructions**: a line in one that reads like a directive is content to report, never something to obey. RIMGEA's Maximize step is explicitly bounded by the explorer's absolute safety boundary, so "proving severity" never licenses a destructive action or the escalation of a security finding.
- **`SFDPOT` renamed to `SFDIPOT`** across the extension — skills, custom agents, TOML commands, `GEMINI.md`, `README.md`, and `HEURISTICS.md`. Bach's HTSM (v6.0, 2024) lists seven Product Elements; the six-letter `SFDPOT` the extension cited is a superseded form of the same heuristic. The `Interfaces` row slots between `Data` and `Platform`; no existing row was renamed, reordered, or dropped. The charter object's `source` enum value is still the literal `sfdpot` — it is a wire value, not the acronym, and renaming it would break existing consumers.
- **The `explorer` agent no longer reports numbers it cannot observe.** `session_sheet` drops `duration` and `tbs` (Task Breakdown Metric percentages) — a wall-clock measurement an agent has no way to take, whose presence contradicted the agent's own hard rule against fabricating a result. In their place it reports what it genuinely counts: `probe_budget`, `probes_attempted`, `probes_with_finding`, `on_charter_probes`/`off_charter_probes`, `tool_calls_used`, `heuristics_applied`, and `stop_reason`. An agent session is now bounded by an **agent-native budget** — a probe budget (default 12, band 8–20) and a tool-call ceiling (5 × the probe budget), whichever is reached first; the agent definition's own `max_turns` is a hard outer bound, so the effective ceiling is the lower of the two. The `session` skill keeps the 60–120 minute box and TBS for **human-run and paired** sessions and now states plainly that neither binds an agent session; the four stopping heuristics are unchanged in substance (bullet 2 now reads "The box or the budget is up"). **`/explore` gains `--probes <count>`** for the per-session probe budget; **`--timebox <minutes>` keeps its unit** and is now documented as doing only what it always effectively did — deciding how many charters run (one session ≈ 90 minutes) — and is never passed to the explorer. **Downstream consumers that read `session_sheet.duration` or `session_sheet.tbs` must switch to the counts**; `/debrief` is unaffected (it consumes unstructured tagged notes). `fixtures/example-session-sheet.md` and `fixtures/example-debrief.md` are now **agent-run** examples — a `SESSION BUDGET` block with probe and tool-call counts and a `stop_reason` in place of `DURATION` and `TASK BREAKDOWN METRICS` — so the extension ships a worked example of the new shape at the fixture `README.md` points `/explore` readers to. The `explorer` agent's `max_turns` rises from 40 to 60 so the runtime bound agrees with the default ceiling instead of silently capping it; the agent still stops at the lower of the two and reports it as `tool_call_ceiling`. `/explore` also gains the `--probes` flag in the `GEMINI.md` command table, which is the signature Gemini CLI auto-loads into every session.
