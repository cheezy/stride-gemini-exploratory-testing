# Changelog

All notable changes to the Stride Exploratory Testing extension for Gemini CLI are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

An accuracy fix for the explorer, and the output contract every stride port reads: the rules that set a bug's severity and end a session now travel inside the agent instead of in skills it may not be able to read, and the explorer's findings now follow output contract `1.0`. The explorer also loses `web_fetch`: it observes HTTP with `curl -sS -i`, judges only what its own tools can observe, and ends a charter it cannot observe with `no_observation_surface`. And the explorer now runs only with two required lines in its environment context: **a direct caller that does not send both `AUTHORIZED_NON_PRODUCTION: yes` and `ALLOWED_HOSTS` gets a `blocked` session with zero probes.**

### Changed

- **The explorer carries an inline explorer card, so its severity values, oracles, RIMGEA and stop rules no longer depend on loading a skill** (W2494, a port of the Claude Code plugin's W2261). `agents/explorer.md` told the agent to read `heuristics`, `oracles`, `bug-advocacy` and `session` by the relative path `skills/<name>/SKILL.md`, which Gemini CLI resolves against the workspace (the project under test), not the extension, so those reads very likely never succeeded. The Claude Code plugin measured the same failure in its own explorer: only 28 of 101 bugs carried one of the rubric's exact severity tokens, and because escalation keys on the literal `Critical`, the drift switched escalation off. The card is 3,951 bytes between `<!-- explorer-card:start -->` and `<!-- explorer-card:end -->`, placed directly after the safety boundary, which is unchanged byte for byte. It holds the exact values `Critical` | `High` | `Moderate` | `Minor` (a bare capitalised word, never omitted) and their order, every impact-ladder clause condensed per level, the tie rule, the three modifiers and their combination rule, the likelihood rule, the unknown-impact rule with its `Provisional` marker, the three oracle verdicts and the three kinds of oracle, RIMGEA mapped onto the `bugs[]` fields it fills, and the stop rules mapped onto the five `stop_reason` values. The wording is this edition's own; no ladder clause moved between levels and no output-contract key was added or removed. The explore loop, the `bugs[]` rows and the session-budget hard rule now point at the card. This ports the card as it landed upstream (v0.3.0). Its `replicated`, `provisional` and `known_bad` mentions arrived with output contract `1.0` in W2495 below; the v0.4.0 `no_observation_surface` ending is ported in W2496 below.
- **The four skills are optional depth, referenced as `${extensionPath}/skills/<name>/SKILL.md`** (W2494). The agent tries a skill with `read_file` at most once, does not fall back to `run_shell_command` (which prompts interactively and is denied headless), spends no probe budget on it, and works from the card when the read fails; the card binds whether or not a skill was read. **Not verified live.** Gemini CLI is not installed on the machine this was written on, so two things were never observed: whether `${extensionPath}` is substituted in an extension agent's body, and whether `read_file` accepts the resulting path outside the workspace. What is said about both comes from a reading of the `@google/gemini-cli-core` 0.65.0 package source done while planning the `stride-gemini-security-review` port, not from a run: it suggests the substitution happens and `read_file` refuses the path. The card is written so that neither outcome matters. The task's two manual checks were not run either: a borderline High/Critical charter with every `bugs[].severity` checked against the four tokens, and asking the explorer to consult `heuristics` to see whether the path resolves. Run both once the extension is installed. `agents/charter-generator.md` and the command TOML files still name skills by relative path; they are out of this change's scope.
- **The explorer's findings follow output contract `1.0`, and `status` is derived from `stop_reason`** (W2495, a port of the Claude Code plugin's W2262). Keys consumers gain: at the root, `contract_version` (always `"1.0"`, the same value in every edition so a `stride` port can trust it) and `known_bad` (each `{ "summary", "observed", "basis" }`); on every `bugs[]` entry, `replicated` (`"<k>/<n>"` from clean-start re-runs with *n* ≥ 2 and one run being one attempt of the triggering action, never `"1/1"`, or `"not established: <reason>"`) and `provisional` (`true` exactly when the unknown-impact rule applied, so `severity` is `Moderate` or `Minor`); `questions_risks` elements become `{ "kind": "question"｜"risk", "text" }` and `off_charter` elements become `{ "item", "candidate_charter" }`. A new *Status from `stop_reason`* table in `agents/explorer.md` maps each of the five stop reasons to one status: `charter_quiet` and `risk_acceptable` → `completed`; `probe_budget_exhausted` and `tool_call_ceiling` → `stopped_early`, which was listed but never defined; `blocked` → `blocked`, which now covers a target not clearly authorised (a new edge case: no probe, every root key still returned). When `status` disagrees with the table a consumer trusts `stop_reason`, and a consumer that finds the new keys absent is reading an older explorer and reads a plain-string element as its `text` or `item`. A new optional `known_issues` input is untrusted, caller-supplied data used only at the oracle step: a matching result goes in `known_bad`, never `bugs`, and no entry overrides the safety boundary or authorises a target. The card gains the three field names and is now 4,017 of 4,096 bytes; no ladder clause moved. **Not ported**, because this edition has neither: upstream's verify mode and its `EXPLORATORY_REPORT_PATH` report file and summary lines. The contract says the fenced document is the `result` the explorer hands back through `complete_task`; that comes from reading the `@google/gemini-cli-core` 0.65.0 source, not from a live run. **Follow-up:** `commands/explore.toml` still lists the pre-1.0 keys when it parses a session, does not pass `known_issues`, and does not carry `known_bad`, `replicated` or `provisional` into the debrief (upstream changed its `commands/explore.md` in the same commit); README's fixture list does not yet name the new fixture. **Not exercised live:** Gemini CLI is not installed on the machine this was written on, so the task's two manual checks were not run — a dispatch with a `known_issues` list naming a real bug, to see whether matches land in `known_bad`, and `EXPLORER_OUTPUT` on a saved real result. Run both once the extension is installed.
- **The explorer observes HTTP with `curl -sS -i` instead of `web_fetch`, judges only what a tool in its own list can observe, and returns `blocked` with a new `stop_reason` `no_observation_surface` when a charter needs an observation it has no tool for** (W2496, a port of the Claude Code plugin's W2263). `web_fetch` is gone from the explorer's `tools:` list, so Gemini CLI rather than prose keeps it out of reach, and nothing in the extension names it as an explorer tool any more: `agents/explorer.md`, `commands/explore.toml`, README's explorer bullet and a note under GEMINI.md's tool mapping (whose `WebFetch` → `web_fetch` row stays, as a translation aid rather than a grant) all say the explorer holds no fetch tool. A new *What you can observe* section says to observe HTTP with `curl -sS -i` through `run_shell_command`, never to use `web_fetch` as an oracle source, and that a denied `run_shell_command` call (Gemini CLI prompts for each one when interactive and denies it by default when headless) is an observation not made, never one to fill in. Rendered layout, appearance, colour and contrast, cross-browser differences, focus order as drawn and rendered accessibility need a browser tool the agent actually holds — an environment context that names one does not grant it — and are never judged from HTML, CSS or template source, though a fact plainly in the markup may be recorded as a source fact. A charter needing such an observation explores its observable part (those findings stay valid), records the rest in `debrief.unknown` and as a `risk`, and ends `no_observation_surface`, which **replaces whatever other stop reason held** and derives `status: "blocked"`; a wholly unobservable charter runs no probes. The `stop_reason` row and the *Status from `stop_reason`* table gain the value, an edge-case bullet covers it, and the card gains a stop bullet; to fit, the card's severity-spelling sentence was shortened, and the card is now 4,092 of 4,096 bytes. The wording is this edition's own; only the pinned rule sentences, enum values and tokens match upstream and the opencode port. **Diverges from upstream on redirects, as the opencode port did:** upstream allows `-L` when following a redirect is itself the probe; this edition forbids `-L`/`--location` and has the agent read the `Location` header and request it only when it names a host the caller authorised, so a redirect can never carry a probe to an unauthorised host. The rule writes the command as `curl -q -sS -i --max-redirs 0 <url>`, so that guarantee does not rest on the operator's curl config: `-q`, which must be the first argument, stops `curl` reading a `.curlrc` whose `location` line would follow redirects with no `-L` on the command line, and `--max-redirs 0` refuses any redirect that still gets through. `contract_version` stays `"1.0"`: a new enum value is not a key, field or element type, and a reader that does not know it still sees `blocked`. `commands/explore.toml` no longer lists `web_fetch` in the explorer's core, notes that richer tools help only when they are in the agent's own `tools:` list, and carries a `no_observation_surface` session as a missing observation surface rather than a failing app, under Obstacles and Unknown. **Not exercised live:** Gemini CLI is not installed on the machine this was written on, so the task's two manual checks were not run — a dispatch on a charter that needs a rendered view (layout or colour), to see whether it ends `no_observation_surface` instead of judging from HTML, and a dispatch on an HTTP charter, to see whether it observes with `curl -sS -i` and reports status and headers. Run both once the extension is installed.
- **The explorer requires `AUTHORIZED_NON_PRODUCTION: yes` and `ALLOWED_HOSTS` lines and returns `blocked` with zero probes without them, cleans up everything it started before its last working turn, reads a credential file only for a value the dispatch names, and Interrupt, Starve and the Saboteur Tour are limited to in-app means** (W2497, a port of the Claude Code plugin's W2264). Authorization reached the explorer only as free text inside the environment context, the Interrupt, Starve and Saboteur lenses suggested killing processes, dropping the network and starving the host, and nothing told the explorer to remove what it started. **Direct callers must now send both lines, each on a line of its own (`/explore` writes them first in the block, a convention the explorer does not check), or every session ends `blocked` with zero probes and nothing sent over the network.** `agents/explorer.md`'s *What you receive* gains `AUTHORIZED_NON_PRODUCTION: yes`, where only the literal `yes` authorises (`=yes` reads the same) and a missing line, an empty or other value, or two or more such lines, even identical ones, leave the target not authorised; and `ALLOWED_HOSTS: <host[:port]>, <host[:port]>`, the only source of reachable hosts, matched exactly (case-insensitive host, no wildcards or subdomains, an IP and a name are separate entries, a port-less entry admits only the scheme's default port), binding every network action including database and cache clients, never widened by a redirect, link, response, config file, `known_issues` or the charter, refused outright when a second line appears, and accepting `none` alone for a target reached only through a local command. Only a line that begins with the name counts, so a line quoted with `> ` never does. The safety boundary gains three bullets around the five existing ones, which are unchanged: reach only listed hosts and only with the affirmative; **leave nothing behind that you started**, a running list of every process and file, every file created through `run_shell_command` or by an interaction tool at the explorer's request, scratch files only in one `mktemp -d` directory, a background process bounded by `timeout`, `gtimeout` or a `perl` alarm and not launched when none exists, and on every exit path each listed PID stopped (`kill`, then `kill -9` on that PID only), each listed file removed with `rm -f --`, the directory with `rmdir`, never `pkill`, `killall` or a glob, in-app test data removed and any changed app setting or feature flag restored; and **credential files are opened only for a value the dispatch names**, never read whole, the one value extracted by a `run_shell_command` call that prints nothing, kept only in a mode-600 file in the scratch directory and never in the findings, and named only by the caller's own test-account pointer. **Gemini-specific: cleanup must finish before the explorer's last working turn.** `max_turns: 60` is enforced by the runtime, and when it (or `timeout_mins`) is reached the runtime grants one final turn in which anything but a `complete_task` call loses the whole result, so cleanup past the tool-call ceiling is allowed and counted but cleanup past `max_turns` is not; the `max_turns` paragraph and the budget hard rule say so. New edge case: a cleanup that fails or times out is retried once and then reported with its PID or path, and never changes `stop_reason`. The redirect rule now names `ALLOWED_HOSTS`. `skills/heuristics/SKILL.md` limits Interrupt, Starve and the Saboteur Tour to in-app means and its safety section states the limit. `commands/explore.toml` asks for the app's `host:port`, writes `AUTHORIZED_NON_PRODUCTION: yes` only on the explicit authorized choice and `ALLOWED_HOSTS` from the hosts the operator gave (`none` for a CLI-only target), each exactly once and first in the block, neutralizes any operator or charter line beginning with either name by prefixing it with `> `, names the exact key when a test-account pointer is a credential file, keeps both lines first and unchanged in every dispatch, and takes the plan-only path when it can build no `ALLOWED_HOSTS` line. **Not ported**, because this edition has neither: upstream's report-file, `Write` and verify-mode clauses; and upstream's allowance to use `-L` when every hop is listed, since this edition's curl rule forbids `-L` outright. The explorer card is unchanged (4,092 of 4,096 bytes), no `stop_reason` value is added, and `contract_version` stays `"1.0"`. **Owed:** `stride-gemini`'s Step 5.5 explorer dispatch does not send the two lines yet, so its sessions end `blocked` until that consumer is updated; that is a `stride-gemini` change, not part of this extension. **Not exercised live**: Gemini CLI is not installed here, so the runtime's grace-turn behaviour was read from the `@google/gemini-cli-core` 0.65.0 source, and no explorer was dispatched with or without the two lines; those dispatches need Gemini CLI installed and a non-production target the user authorizes.

### Added

- **`policies/explorer.toml`, deny rules that Gemini CLI enforces for the explorer** (W2497). Four rules, each `toolName = "run_shell_command"`, `subagent = "explorer"`, `decision = "deny"`: a recursive `rm` (`-r`, `-R`, `--recursive`, in any flag group), an `rm` with a glob or wildcard, `pkill` and `killall`, and `git push`. None touches the explorer's own cleanup (`kill <pid>`, `kill -9 <pid>`, `rm -f -- <path>`, `rmdir`). **Why ship one, and why only deny:** a Gemini CLI extension may contribute policies from `policies/*.toml` at the Extension tier, but the runtime drops any `allow` rule and any rule listing yolo mode from an extension, so deny is the only decision that has an effect; no rule sets `modes`, so each applies in every approval mode, interactive and headless. The rules back up the prose boundary rather than replace it: they are best-effort (a command wrapped in `sudo`, `xargs`, `timeout` or a quoted argument can slip past), and a User, Workspace or Admin policy outranks them. Both regexes avoid a quantified group, because the runtime silently drops a pattern its ReDoS screen flags. **Verified against the runtime's own code:** the file was loaded with `loadExtensionPolicies` and checked with `PolicyEngine.check` from the `@google/gemini-cli` 0.65.0 bundle, with no load errors: as the `explorer` subagent `rm -rf`, `rm -f -r`, `rm --recursive`, `rm -R`, `rm -f <dir>/*`, `pkill`, `killall`, `git push --force` and `echo hi && rm -rf /` were denied, while `kill <pid>`, `kill -9 <pid>`, `rm -f -- <path>`, `rmdir` and `curl -q -sS -i --max-redirs 0` were not; with no subagent nothing was denied. Not exercised in a live Gemini CLI session. `install.sh` and `install.ps1` now copy `policies/`.

## [0.2.0] - 2026-08-01

A capability sweep ported from the Claude Code plugin's 2026-07 improvement research: two new commands, a sixth skill, session artifacts that survive the conversation, and an explorer contract that no longer asks the agent to fabricate.

### Added

- **`/pair` command** (`commands/pair.toml`) — an exploratory session with a **human at the keyboard**, the inversion of `/explore`. The human drives the application and reports what they did and saw; the command suggests one probe per round and **names the `heuristics` lens it came from**, judges each report with `oracles`, runs RIMGEA on confirmed defects as instructions to the human, and keeps the SBTM session sheet and off-charter parking lot so the tester never context-switches into note-taking. Its signature work is the **unprompted coverage-gap sweep**: three ledgers (areas, the nine Variable Catalog rows, and seven fixed stances — valence, tenancy, role, character set, volume, sequence/concurrency, entry point) swept at fixed points, each gap raised at most once, with a declined gap going to the backlog rather than being lost. It measures only what it can observe — duration from two real `date` stamps, Task Breakdown Metrics marked *derived* unless the tester confirms them, and never a response time it did not see. It writes a session sheet and appends to the backlog, deliberately **not** the coverage outline, and hands off to `/debrief`. **It never drives the application and never dispatches the `explorer`.** Note that a Gemini TOML command has no tool allowlist, so unlike the Claude original that boundary is held by the command's own rules rather than by a withheld tool — the command says so plainly rather than claiming an enforcement it does not have.
- **`/harden` command** (`commands/harden.toml`) — the bridge from *Explored* back to *Checked*. It reads a session's oracle-confirmed bugs (from an explorer findings object, a `/pair` sheet, an `/explore` debrief, or pasted findings), **detects the project's own test framework** from its markers, existing tests, and config across nine ecosystems — reporting what it detected and on what evidence **before anything is written** — and drafts one regression check per convertible bug, built from the bug's isolated `minimal_repro`. A bug is convertible only with a stated trigger, a stated wrong result, a programmable observation, and a safe repro; everything else is reported not-converted under one of seven categories with the one thing that would fix it, because a guessed repro produces a check that passes for the wrong reason. Drafts never hard-code a secret, never point at a real host, and never perform a destructive action. They are staged under `.exploratory/checks/<timestamp>-<slug>/` with an `INDEX.md`, nothing is ever overwritten, and **it never runs a draft and never says one passes** — a rule the command holds itself, stated as such, since a Gemini TOML command has no allowlist that could withhold a shell from it.
- **`bug-advocacy` skill** (`skills/bug-advocacy/SKILL.md`) — the sixth skill, and the one that picks up where `oracles` stops. It encodes Cem Kaner's **RIMGEA** follow-through (Replicate, Isolate, Maximize, Generalize, Externalize, And say it clearly), each step with a definition and the prompt to ask, plus a **severity rubric a second reader can re-derive**: four named levels, an impact ladder of explicit clauses, three aggravating modifiers with a stated combination rule, an agreement test, and the two-door procedure for when the impact is genuinely unknown. `severity` was already a required field of the explorer's `bugs[]` contract and was defined nowhere — this is where it now comes from. Routed from `oracles` (at the moment a result is judged a Defect) and from the orchestrator's routing table.
- **Session artifacts on disk** — sessions now persist to `.exploratory/` in the project under test: `backlog.md` (append-only candidate/deferred charters, parked items, and open questions), `coverage.md` (the product coverage outline — a map, explicitly never a score), and `sessions/<timestamp>-<slug>.md` (one debrief per `/explore` run). The `session` skill owns the tree, the formats, the header blocks, and the read-immediately-before-write mechanics. **A missing artifact is an empty starting state, never an error**, so a first run in a new project simply creates what it needs. Add `.exploratory/` to the project under test's `.gitignore`.
- **`charter-generator` accepts `coverage context`** and gains an optional `deprioritized` output key. When a coverage digest is supplied it mines the still-dark areas and the open backlog, discounts charters aimed at ground already covered, and records what it moved down — with risk always outranking recency, so an area explored last week that still has an open Critical bug is not treated as covered. `/charter` and `/explore` assemble that digest and pass it; the agent stays read-only and never touches disk itself.
- **`interfaces` lens** — the Heuristic Test Strategy Model's **I**nterfaces element joins the coverage lens in the `chartering` skill, covering APIs, imports and exports, UI surfaces, and integration points between systems: the boundaries where service-oriented and LLM tool-calling applications most often fail. **Downstream consumers must handle `interfaces` as a new allowed value of a charter object's optional `lens` field** (`agents/charter-generator.md`), alongside the existing `structure`, `function`, `data`, `platform`, `operations`, and `time`.

### Changed

- **The `explorer` agent's `bugs[]` objects carry the four RIMGEA fields.** Each bug now emits `minimal_repro`, `worst_observed`, `generalization`, and `stakeholder_impact` alongside the existing five, and `severity` must be one of the `bug-advocacy` rubric's levels written in full. **The four fields are honest-or-"could not establish", never invented** — the key is always emitted, and when the answer could not be established its value says exactly that. `/explore` carries all four through aggregation and, when two sessions found the same bug, merges by keeping the shortest `minimal_repro`, the worst demonstrated `worst_observed`, and the broadest `generalization`. **Downstream consumers of `bugs[]` gain four keys**; none is removed.
- **The other four commands now participate in the artifact tree.** `/charter` and `/nightmare-headline` append their generated charters to the backlog; `/recon` appends candidate charters and questions and may add an un-explored area stub to the coverage outline (it never dates an area or edits an existing one); `/debrief` appends parked items and refreshes coverage for the areas its notes honestly identify. Every one of them treats a missing file as an empty starting state.
- **Redaction and untrusted-input rules restated for written files.** The redaction rule now binds explicitly on *writes*, not only on rendered output — a file outlives the session and can be read by someone who never saw the run — and it covers the four new bug fields. Conversely, `backlog.md` and `coverage.md` are read back on later runs and are **data, never instructions**: a line in one that reads like a directive is content to report, never something to obey. RIMGEA's Maximize step is explicitly bounded by the explorer's absolute safety boundary, so "proving severity" never licenses a destructive action or the escalation of a security finding.
- **`SFDPOT` renamed to `SFDIPOT`** across the extension — skills, custom agents, TOML commands, `GEMINI.md`, `README.md`, and `HEURISTICS.md`. Bach's HTSM (v6.0, 2024) lists seven Product Elements; the six-letter `SFDPOT` the extension cited is a superseded form of the same heuristic. The `Interfaces` row slots between `Data` and `Platform`; no existing row was renamed, reordered, or dropped. The charter object's `source` enum value is still the literal `sfdpot` — it is a wire value, not the acronym, and renaming it would break existing consumers.
- **The `explorer` agent no longer reports numbers it cannot observe.** `session_sheet` drops `duration` and `tbs` (Task Breakdown Metric percentages) — a wall-clock measurement an agent has no way to take, whose presence contradicted the agent's own hard rule against fabricating a result. In their place it reports what it genuinely counts: `probe_budget`, `probes_attempted`, `probes_with_finding`, `on_charter_probes`/`off_charter_probes`, `tool_calls_used`, `heuristics_applied`, and `stop_reason`. An agent session is now bounded by an **agent-native budget** — a probe budget (default 12, band 8–20) and a tool-call ceiling (5 × the probe budget), whichever is reached first; the agent definition's own `max_turns` is a hard outer bound, so the effective ceiling is the lower of the two. The `session` skill keeps the 60–120 minute box and TBS for **human-run and paired** sessions and now states plainly that neither binds an agent session; the four stopping heuristics are unchanged in substance (bullet 2 now reads "The box or the budget is up"). **`/explore` gains `--probes <count>`** for the per-session probe budget; **`--timebox <minutes>` keeps its unit** and is now documented as doing only what it always effectively did — deciding how many charters run (one session ≈ 90 minutes) — and is never passed to the explorer. **Downstream consumers that read `session_sheet.duration` or `session_sheet.tbs` must switch to the counts**; `/debrief` is unaffected (it consumes unstructured tagged notes). `fixtures/example-session-sheet.md` and `fixtures/example-debrief.md` are now **agent-run** examples — a `SESSION BUDGET` block with probe and tool-call counts and a `stop_reason` in place of `DURATION` and `TASK BREAKDOWN METRICS` — so the extension ships a worked example of the new shape at the fixture `README.md` points `/explore` readers to. The `explorer` agent's `max_turns` rises from 40 to 60 so the runtime bound agrees with the default ceiling instead of silently capping it; the agent still stops at the lower of the two and reports it as `tool_call_ceiling`. `/explore` also gains the `--probes` flag in the `GEMINI.md` command table, which is the signature Gemini CLI auto-loads into every session.
